# 工程照片 AI 交叉稽核系統（image-audit）

以「像素初篩 + DINOv2 特徵比對」的兩段式流程，找出跨資料夾重複出現的工程照片，用於查核重複請款、照片重複使用等情形，並可一鍵匯出 Word 查核報告。

**不需要 API Key、不需註冊、照片不外傳**：相似度計算用的 DINOv2 模型直接在瀏覽器本機執行。

線上使用：<https://ymguan3-boop.github.io/original-tools/image-audit/>

## 功能

| 步驟 | 說明 |
|------|------|
| 交叉比對 | 加入 2 個以上資料夾（整個資料夾上傳），以 64×64 中心裁切像素特徵兩兩比對，列出相似度達門檻的組合 |
| 第一步 | 依像素相似度區間統計（95-100%、90-94%…），可點卡片篩選；可批次刪除低於指定門檻的組別 |
| 第二步 1 | 以 **DINOv2-small 在本機** 為每組計算 384 維特徵的餘弦相似度（0-100），判斷是否為同一張照片 |
| 第二步 2 | 批次刪除 DINOv2 分數低於指定門檻的組別（預設 90%） |
| 第三步 | 產出「差異度說明」與「分析結論」：有填 OpenRouter 金鑰時，分數最高的前 N 組交給 AI 撰寫，其餘（及未填金鑰時全部）用內建規則模板 |
| 第四步 | 匯出 `.doc` 報告（含雙圖對照、像素分數、DINOv2 分數與結論） |

## 相似度引擎：DINOv2-small（本機執行）

- 模型：`Xenova/dinov2-small`（ONNX，`q8` 量化，約 **23MB**），透過 `@huggingface/transformers` 在瀏覽器以 WebAssembly 執行。
- 首次點「1. 相似度分析」時才下載模型，之後由瀏覽器快取（IndexedDB），第二次起幾乎立刻可用。
- 每張圖只推論一次並快取特徵向量（`WeakMap`），因此同一張照片在多組配對中只算一次；比對本身只是 384 維向量的餘弦相似度，瞬間完成。
- 單張推論約 300–530ms（一般筆電），一張照片平均不到 1 秒。
- **照片不會離開瀏覽器**：這一步完全離線運算，沒有網路請求。

### 分數參考（實測）

| 情境 | DINOv2 分數 |
|------|-------------|
| 同一張圖（重新壓縮） | 100 |
| 同一張圖但亮度／色偏明顯 | 約 95–96 |
| 同一張圖裁切、縮放 | 約 94–95 |
| 同場景不同解析度 | 約 94 |
| 完全不同內容 | 約 33 |

因為 DINOv2 分數分佈偏高（不像像素比對會直接掉到 50 以下），第二步的刪除門檻預設為 **90%**。

## 文字說明引擎：OpenRouter（選配）

不填金鑰也能完成整個流程。填了金鑰，第三步會把分數最高的前 N 組（預設 20 組）連同兩張縮圖送給視覺模型，請它寫差異說明與結論。

- 端點與 OpenAI Chat Completions 相容，圖片以 `image_url` + data URL 傳入。
- 下拉選單會即時向 OpenRouter `/api/v1/models` 抓取**免費且支援圖像**的模型；預設 `nvidia/nemotron-3.5-super-vl:free`。
- 免費模型限制：每分鐘約 20 次請求，程式已把呼叫間隔設為 3.2 秒；遇到 429 / 5xx 會依 `Retry-After` 退避重試最多 3 次。
- 單筆失敗會自動退回規則模板，不讓報告留白；401/402/403/404/429 視為致命錯誤並中斷整批。

### 金鑰與隱私

- **金鑰只存在使用者自己的瀏覽器**（`localStorage`），不經過本專案任何伺服器；只送給 OpenRouter。
- 只有第三步（且限前 N 組）才會把**縮至 1024px 的 JPEG 縮圖**送出。
- 本倉庫不含任何金鑰，請勿把金鑰寫進程式碼或提交上傳。

### 取得免費金鑰

1. 前往 <https://openrouter.ai/keys> 註冊 / 登入。
2. 建立 API Key（`sk-or-v1-...`）。
3. 貼進頁面上方的「文字說明（選配）」輸入框即可，下次開啟會自動帶入。

## 開發

```bash
npm install
npm run dev      # http://localhost:5174/original-tools/image-audit/
npm run build    # 產出 dist/
```

`vite.config.ts` 的 `base` 設為 `/original-tools/image-audit/`，對應 GitHub Pages 子路徑；若改為獨立網域部署需一併調整。

## 技術重點

- **像素比對**：中心裁切後縮為 64×64，逐像素計算 RGB 平均差，換算為 0-100 相似度。純前端、可離線、速度快，用來先砍掉大量明顯不同的組合。
- **DINOv2 特徵**：`pipeline('image-feature-extraction', ...)` 回傳 `last_hidden_state`（`[1, 257, 384]`），取 CLS token 的前 384 維，自行除以 L2 範數後算餘弦相似度，避免依賴上游 normalize 行為。
- **建置產物**：transformers.js 會把 ONNX Runtime 的 WASM 打包成獨立檔案（約 26.8MB），vite 的 chunk 大小警告屬正常。
- **圖片 URL 快取**：以 `WeakMap` 快取 `ObjectURL`，避免每次 render 重建造成記憶體洩漏。
- **錯誤處理**：模型載入失敗（例如內網封鎖 huggingface.co、瀏覽器阻擋 WASM）會顯示提示，第一步的像素比對仍可使用。
