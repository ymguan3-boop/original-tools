# 工程照片交叉稽核系統（image-audit）

**版本分流（2026-10-31）：**

- **[選擇使用版本](https://ymguan3-boop.github.io/original-tools/image-audit/selector.html)**：先選擇 DINOv2 桌面 ZIP 或線上輕量版。
- **[Windows DINOv2 桌面 ZIP](https://ymguan3-boop.github.io/original-tools/image-audit/image-audit-desktop-dinov2.zip)**：本機 DINOv2-small、量化 ONNX 與 WASM 已包進 ZIP。解壓後雙擊 `啟動工程照片稽核.exe`，由 Windows 本機啟動器開啟瀏覽器，**無須安裝 Python**。完整安裝步驟已放在[版本選擇與下載頁](https://ymguan3-boop.github.io/original-tools/image-audit/selector.html#desktop-guide)，桌面 ZIP 不再附安裝說明 TXT。依瀏覽器安全限制，DINOv2 版無法保證直接雙擊 `file://` HTML 運作。
- **[線上輕量版](https://ymguan3-boop.github.io/original-tools/image-audit/)**：免下載、免 DINOv2，使用像素、感知雜湊與色彩特徵組合進行照片相似度初篩，支援 Word／CSV 匯出。
- **[舊版直接雙擊 HTML ZIP](https://ymguan3-boop.github.io/original-tools/image-audit/image-audit-desktop-html-offline.zip)**：保留為相容下載，不包含 DINOv2，適合只能開啟 HTML 的環境。

> 兩種演算法不可直接混用分數，照片相似度僅能作查核線索，仍須核對日期、工程日誌、契約及驗收資料。原下方 DINOv2 功能與技術說明屬「Windows DINOv2 桌面版」，並非現行線上輕量版。

> **桌面版打包說明（2026-10-31）**：ZIP 必須保留 `index.html`、`assets/`、`models/` 與 `docxWriter.js` 等程式資源。EXE 僅負責啟動 `127.0.0.1` 本機伺服器，並讀取 `index.html` 提供操作介面。**不可單獨刪除 HTML 或只取出 EXE 執行**；ZIP 中原獨立的 `使用說明.txt` 則已移至下載頁，故不再打包。

## OpenRouter 一致化查核報告 v1.0（2026-10-31）

桌面版、線上版與免安裝 HTML 版都採共用報告格式。OpenRouter 只提供雙圖可見的相同點、差異與查證建議；模型回傳需通過 JSON 欄位驗證，系統會排除 AI 自行編造的數值與未經證實的確定性結論。

報告固定六段：① 照片可見相同點、② 可見差異、③ 客觀比對證據、④ 查核研判、⑤ 待查證事項、⑥ 來源與判讀限制。第三段只使用本機演算法測得的指標；第四段分開列出系統查核優先度與 AI 觀察推論；第六段記錄分析來源、AI 模型（若有）、產製時間與回退原因。

如果 OpenRouter 服務失敗、無法回傳完整 JSON 或觀察內容不足，系統會以相同六段式規則模板補齊，並明確標示沒有進行雲端雙圖視覺觀察。規則說明完成後，桌面版仍可用 OpenRouter 補做後續判讀。DOCX、CSV 及畫面均取自同一份分析說明。

未新增其他 LLM 服務，也未改動共同視覺評分公式，沒有建立真實工程照片驗收資料集。所有結果均須由審計人員核對原始照片、施工日誌、拍攝日期、契約、估驗計價及驗收資料。

## 2026-10-31 精準查核改版｜網頁維持輕量，桌面按需深化

**兩版共同初篩（不變）：** pHash（感知雜湊）、dHash（亮暗差異）、32×32 明暗結構、邊緣一致性、RGB 像素輔助、色彩直方圖、全圖及中心裁切、小範圍位移校正。基礎權重：pHash 38%、結構 33%、邊緣 18%、dHash 11%；包含可信度上限與多證據補正，最終數值非單純線性平均。原有線上版不加載 DINOv2、SAM、YOLO 或 Grounding DINO；避免牽動速度、記憶體與瀏覽器相容性。

**Windows DINOv2 桌面版：** 保留全批次共同分數，另顯示 DINOv2-small CLS 語意特徵；Worker 僅在模型確有 patch token 輸出時，提取 4×4 區域 DINOv2 patch 特徵，缺失時顯示「模型未回傳」，不捏造。詳細檢視的「進階驗證」才啟動純本機 FAST 角點、方向 BRIEF 128-bit 描述子、互相最佳比對、RANSAC 旋轉／尺度／位移相似變換、對齊後 8×8 視窗 SSIM、紅色差異熱區與 SHA-256 同檔驗證。進階結果會附在 DOCX 查核說明中，但**不會改動共同分數／排序／篩選門檻**。相關實作在 `src/advancedVision.ts`。

**不是完整 OpenCV ORB / Homography：** 目前為不需額外大型 WASM 的自有 FAST / 方向 BRIEF ＋相似變換 RANSAC，還不能將一般透視變形等同處理；不等於實驗室鑑識結論。MobileSAM、SAM 2、Grounding DINO、YOLO 不納入本次離線包，主要是因為模型大小、提示／物件選擇與高效推論管線未完成驗證。沒有建立工程驗收標註資料集；目前僅以程式測試驗證介面、可離線載入及指標功能。

**安全判讀：** 任何相似度與物件一致性都不表示違規機率。若同一原始照片跨批次出現，仍需審查 EXIF、原始檔、日期、位置、估驗計價及驗收資料。DINOv2 與新增加的進階數據皆為輔助證據，不應與共同視覺分數混為同一個百分比。

## 操作流程（3 步）

| 步驟 | 說明 |
|------|------|
| 1. 開始分析 | 加入 2 個以上資料夾（整批上傳），按一次即完成全部配對評分：**DINOv2 特徵相似度為主分數**，像素相似度為輔助欄位。清單只列出達「列出門檻」的組合，可依分數區間篩選、單筆刪除，或批次刪除低於指定門檻的組別 |
| 2. 產生差異說明及結論 | 為每組產出「差異度說明」與「分析結論」。有填 OpenRouter 金鑰時，分數最高的前 N 組（預設 20 組）交給視覺模型撰寫，其餘（含未填金鑰時全部）用內建規則模板 |
| 3. 匯出 WORD 報告 | 匯出 `.docx` 報告（雙圖對照、DINOv2 分數、像素分數、差異說明與結論） |

> 為什麼只有一次分析：DINOv2 必須把每張「唯一的圖」都算過一次，這個成本無法省略；而向量比對（餘弦相似度）幾乎不花時間。所以「先用像素初篩、再把剩下的丟給 DINOv2」省不到任何時間，只是多付一次全對全比對與一次解碼。像素分數因此改為輔助參考。

## 相似度引擎：DINOv2-small（本機執行）

- 模型：`Xenova/dinov2-small`（ONNX，`q8` 量化，約 **23MB**），透過 `@huggingface/transformers` 在瀏覽器以 WebAssembly 執行。
- 首次分析才下載模型（頁面上方會顯示下載百分比），之後由瀏覽器快取。
- 每張唯一照片只推論一次；比對本身只是 384 維向量的餘弦相似度，瞬間完成。
- 模型載入失敗（內網封鎖 `huggingface.co`、瀏覽器阻擋 WebAssembly）時會自動退回「像素比對」模式並顯示提示，流程仍可走完。

### 分數參考（實測）

| 情境 | DINOv2 分數 |
|------|-------------|
| 同一張圖（含重新壓縮） | 100 |
| 同一張圖但亮度／色偏明顯 | 約 95–99 |
| 同一張圖裁切、縮放 | 約 93–97 |
| 同場景不同角度／螢幕截圖相似 | 約 80–90 |
| 完全不同內容 | 通常低於 40 |

因為 DINOv2 分數分佈偏高（不像像素比對會直接掉到 50 以下），刪除門檻預設為 **90%**。

## 效能與正確性設計

| 機制 | 原因 |
|------|------|
| 全部運算移到 Web Worker | 主執行緒不會被推論卡住，分析期間仍可點選篩選、捲動清單 |
| **逐張推論**（而非批次） | q8 量化模型的縮放參數是對整個張量（含 batch 維度）計算的，同一張圖若與不同鄰居併批，向量會浮動約 0.7%，導致完全相同的照片只拿 97–99 分。逐張推論的結果完全可重現（cos = 1.000），重複照片會確實拿到 100 分 |
| 內容雜湊（SHA-256）重用 | 位元組完全相同的檔案直接沿用已算好的特徵與縮圖，不重複推論。稽核場景常是同一批照片分散在多個資料夾，這一步省下的時間最多 |
| IndexedDB 嵌入快取 | 已算過的特徵向量與縮圖存到瀏覽器 IndexedDB；重跑同一案件或跨分頁使用時直接命中，省下整次推論。頁面上方「影像引擎」列有「清除快取」按鈕 |
| 480px 縮圖 + 分頁 | 清單只載入縮圖（原始檔僅在「詳細檢視」載入），記憶體不會隨組數暴增；每頁 30 組、最多保留 2000 組 |
| 可停止 | 分析中可按「停止」，Worker 會直接終止，之後可重新開始 |

實測速度（一般筆電，Chrome）：每張唯一照片約 **0.5 秒**（含解碼、縮圖、特徵抽取）；20 張、8 張為重複檔的案例約 8–10 秒完成。

## 文字說明引擎：OpenRouter（選配）

不填金鑰也能完成整個流程。填了金鑰，第 2 步會把分數最高的前 N 組連同兩張縮圖送給視覺模型，請它寫差異說明與結論。

- 端點與 OpenAI Chat Completions 相容，圖片以 `image_url` + data URL 傳入（縮至長邊 1024px）。
- 下拉選單會即時向 OpenRouter `/api/v1/models` 抓取**免費且支援圖像**的模型；預設 `nvidia/nemotron-3.5-super-vl:free`。

- 單筆失敗會自動退回規則模板，不讓報告留白；401/402/403/404/429 視為致命錯誤並中斷整批。

## 技術重點

- **Worker 分工**：`src/embedWorker.ts` 負責解碼、縮圖、64×64 像素特徵與 DINOv2 推論；`src/dinoClient.ts` 以單例包裝 Promise 化的 `init()` / `analyze()` / `terminate()`，並回報模型狀態與下載進度。
- **嵌入快取**：`src/embedCache.ts` 以 SHA-256 為 key，把向量、像素特徵與縮圖存到 IndexedDB；內容定址，檔案不變就不失效。
- **一次解碼**：`createImageBitmap` 後在同一張 `OffscreenCanvas` 上同時產生 JPEG 縮圖（清單用）與推論輸入（`RawImage.fromCanvas`），不經過「編碼 JPEG 再解回來」的重複工作。
- **DINOv2 特徵**：`pipeline('image-feature-extraction', ...)` 回傳 `last_hidden_state`，取 CLS token 的前 384 維，自行除以 L2 範數後算餘弦相似度。
- **像素比對**：中心裁切後縮為 64×64，逐像素計算 RGB 平均差，換算為 0-100 相似度。
- **建置產物**：transformers.js 會把 ONNX Runtime 的 WASM 打包成獨立檔案（約 26.8MB），且整包被拆到 worker chunk，主程式 bundle 僅約 194KB；vite 的 chunk 大小警告屬正常。
- **匯出報告**：圖片以長邊 1280px、JPEG 0.8 內嵌，避免報告檔過大。
